# 按需攝影機問答

這個功能已接入原有的本地 AI 聊天介面，不依賴 YOLO，也不持續執行視覺推論。

## 使用

1. 開啟原本的聊天網站並登入。
2. 按輸入框上方的「開啟攝影機」，允許瀏覽器使用相機。畫面只作本機預覽，尚未送給模型。
3. 保持「自動判斷」勾選。輸入「我手上拿什麼？」或「幫我看看桌上的東西」，AI 判斷需要畫面時才拍一張。
4. 若自動判斷不如預期，勾選「這次附上畫面」再送出。取消「自動判斷」即可只靠手動附圖。
5. 「預覽與設定」可選攝影機和已安裝的視覺模型。收起預覽不會關閉攝影機；停止使用時請按「關閉攝影機」。關閉網頁也會釋放相機。

一般聊天仍走原有的聊天模型。拍照問答會由所選視覺模型直接回答，並保留目前對話的文字模型選擇。若選中的聊天模型本身支援圖片，會優先選同一個模型處理照片。

手動附圖只影響下一次送出，切換對話會取消。已有檔案附件時優先使用附件，不會同時偷偷拍照；若同時勾選手動拍照，會提示先移除附件。

## 照片與歷史紀錄

每次只傳當下的一張 JPEG 到原有網站後端，再送到該後端設定的本機 Ollama。照片留在記憶體，不寫入聊天附件或磁碟。網頁可顯示本次送出的縮圖，關閉相機、切換對話或離開網頁會清除縮圖。

問題與回答會依原有帳號權限保存。歷史文字可作背景，但不會重新傳送以前的照片，也不代表 AI 持續觀察畫面。原本的圖片附件功能仍照原本方式保存附件。

## 模型與效能

本機已驗證 `llava:latest` 與 `hf.co/empero-ai/Qwythos-9B-v2-GGUF:Q4_K_M` 的圖片問答。畫面設定只列出 Ollama 宣告支援 vision 的已安裝模型。

2026-10-11 使用內建公開公車範例圖片測試，LLaVA 的端點總耗時約 42 秒；Qwythos 約 47 秒，其中載入約 15 秒。當時 Ollama 回報 Qwythos 的 `size_vram` 為 0，即 CPU 執行；這不是 RTX 3080 GPU 推論效能，也不是每次都會相同的等待時間。原對話中的 0.5–2 秒是估計，並非本機實測。前端會顯示每次實際分析耗時。

視覺模型可以辨識比 COCO 80 類更廣的內容，但仍會漏看或誤判，尤其是小物件、模糊畫面、部分遮擋及品牌字樣。

## 連線與錯誤

相機需使用 localhost、127.0.0.1 或 HTTPS 網址。普通 HTTP 的遠端 IP 網址通常無法使用相機。瀏覽器未授權時先調整網址列的相機權限。

若攝影機被其他程式占用，先關閉 YOLO 攝影機辨識、Teams 或其他相機程式再試。自動分類失敗時不會偷偷附圖或自動重拍；可手動指定附圖後重試。

## 修改檔案

- `webcam-analysis.js`：已驗證使用者登入後的模型查詢、問題分類、圖片問答。
- `public/webcam.js`、`public/webcam.css`：相機預覽、擷取、狀態與設定。
- `server.js`、`public/index.html`、`public/app.js`：接入原有聊天流程。

原始版本會在原專案的 `webcam-code-backup-*` 資料夾備份，只備份程式碼，不變更既有聊天資料庫。
